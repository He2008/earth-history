# 测试版部署指南(2026-10-26 实测)

> 实测口径:macOS 本机,`node .next/standalone/server.js`,全部命令已验证。
> 合规口径(PRD):个人主体,M2 公测前不备案不公开运营——测试版跑**本机/内网**或**海外 VPS + 自有域名**。

## 一、本机 / 内网测试版(已验证)

```bash
# 1. 构建(产出 .next/standalone)
npm run build

# 2. 拷贝静态资源 —— standalone 不含它们,漏了页面白屏(实测坑 ①)
cp -r .next/static .next/standalone/.next/static
[ -d public ] && cp -r public .next/standalone/public

# 3. 环境文件:必须在 .env 基础上把 DB_PATH 写成绝对路径 ——
#    standalone 的 server.js 会 process.chdir(__dirname),相对路径会落到
#    .next/standalone/data/ 下建一个空库:缓存全丢、分享 token 全 404(实测坑 ②)
cat .env > /tmp/prod.env
echo "DB_PATH=$PWD/data/shidi.db" >> /tmp/prod.env

# 4. 起服务(Node ≥20 的 --env-file;HOSTNAME=0.0.0.0 供局域网访问)
PORT=3211 HOSTNAME=0.0.0.0 node --env-file=/tmp/prod.env .next/standalone/server.js
```

验证三板斧(免花销):

```bash
curl -o /dev/null -w '%{http_code}' localhost:3211/            # 200
curl -o /dev/null -w '%{http_code}' localhost:3211/share/<token> # 200(验 DB 绝对路径)
# 缓存回放:POST /api/research 用任一已研究过的地点 → "cached":true 且 <100ms
```

**排查提示(实测坑 ③)**:改配置重启前先 `lsof -ti :<端口>` 确认旧进程已死——`pkill` 偶尔失手,新进程 EADDRINUSE 静默失败,你会一直测到旧进程还以为配置没生效。被删库文件的旧进程能靠已打开的句柄继续服务,表象极其迷惑。

## 二、海外 VPS(推荐形态)

测试版要跑 10 分钟级长任务 + SSE 长连接,**必须常驻进程**——Vercel/_serverless 不适用(掐长连接+临时文件系统,SQLite 无法持久)。VPS 步骤:

```bash
# 服务器上(Linux, Node ≥20)
git clone https://github.com/He2008/earth-history.git && cd earth-history
npm install              # .npmrc 已指向 npmmirror;better-sqlite3 优先用 prebuild,失败才本地编译(需 python3+make)
npm run build
cp -r .next/static .next/standalone/.next/static
cat .env.example > prod.env   # 填 DEEPSEEK_API_KEY / TIANDITU_KEY_SERVER / TIANDITU_KEY_BROWSER
echo "DB_PATH=$(pwd)/data/shidi.db" >> prod.env
PORT=3000 HOSTNAME=0.0.0.0 node --env-file=prod.env .next/standalone/server.js
```

常驻建议:先用 `nohup` 或 `pm2 start server.js --env-file...`(pm2 不支持 --env-file,用 `pm2 start env DB_PATH=... -- node ...` 或 systemd)。数据卷:`data/` 目录定期备份(全部任务/报告/缓存都在这一个 SQLite 文件里)。

反代(nginx)注意:SSE 需要 `proxy_buffering off;`(响应已带 `X-Accel-Buffering: no`,nginx 默认尊重);`proxy_read_timeout` ≥ 700s(任务硬上限 10 分钟 + 心跳 15s)。

## 三、部署检查清单

- [ ] `DB_PATH` 绝对路径(坑 ②)
- [ ] `.next/static` 已拷贝(坑 ①)
- [ ] 旧进程确认已死再起新进程(坑 ③)
- [ ] 天地图 key 域名白名单:当前 key 若为空白名单则任意来源可用;若设过白名单,加上部署域名(浏览器 key);`localhost` 不用加
- [ ] `data/` 定期备份(SQLite 单文件)
- [ ] 反代:proxy_buffering off + read_timeout ≥700s(如有)
- [ ] 首页/分享页/一次缓存回放 三板斧验证
