# 「史地」— 中文历史地球 产品需求文档

> 版本 v0.1(草案)· 状态:**待批准**
> 参照项目:yorkeccak/history(MIT,仅作架构参考,不直接 fork 改皮)

---

## 1. 产品定位

**一句话**:一个 3D 卫星地球,点击地球上任意地点——尤其是中国境内的县城、古村、无名山海——AI 深度检索中文史料(地方志、官媒档案、学术论文、非遗库),几分钟内产出带引用来源的中文历史报告。

**核心差异**(对照 yorkeccak/history):

| 维度 | yorkeccak/history | 史地 |
|---|---|---|
| 检索源 | 英文库(Wikipedia/arXiv/PubMed/SEC) | 中文互联网 + 地方志 + 官媒 + 学术库 |
| 报告语言 | 英文 | 中文 |
| 中国小地点深度 | 弱(英文资料少) | 强(核心卖点) |
| 研究引擎 | Valyu 单点依赖(美元计费) | 自建编排,搜索/LLM 双层可替换 |
| 地图 | Mapbox(国内访问差) | 天地图(官方、免费额度、无坐标偏移) |
| 合规 | 无 | ICP + AI 内容标识 + 审图路线内置于架构 |

**不做的事(Not building)**:
- 不做通用问答/聊天机器人,只做"地点 → 历史"单向深研
- 不做 UGC 百科(社区贡献放 P2 再议)
- 不做海外地点的深度优化(英文源检索保留但不投入专门 prompt)
- MVP 不做 App/小程序,Web 响应式优先

## 2. 目标用户与场景

**核心用户**:
1. **地图漫游者**(与原项目作者同类):深夜刷卫星图,点到一个诡异的地方想知道它的故事
2. **文史爱好者/研究者**:快速获取某地沿革脉络和资料线索(报告即文献综述入口)
3. **旅行者**:出发前了解目的地的历史纵深
4. **学生/教师**:地理、历史课的探究工具

**典型场景**:
- 用户在卫星图上看到云南某峡谷里有个村,点击 → 3 分钟后得到:该村所属县的建制沿革(汉→唐→明清)、民族构成、茶马古道角色、现存文物、资料来源清单
- 用户搜"我的家乡 XX 县" → 得到从秦汉设郡到当代的完整时间线 + 可引用来源

## 3. 功能需求

### P0(MVP,必须有)

| # | 功能 | 验收标准 |
|---|---|---|
| F1 | 3D 卫星地球 | MapLibre GL + 天地图卫星瓦片,拖拽/缩放/自动旋转,移动端流畅 |
| F2 | 点击选点 + 逆地理编码 | 点击任意点返回中文地名(省/市/县/村层级,按缩放级别匹配粒度);备选方案:天地图逆编码稳定到区县,村级粒度改用民政部行政区划县界数据做坐标空间查找,村名留给研究阶段从县志/搜索资料反推 |
| F3 | 深度研究流水线 | 自建编排:研究规划 → 多轮搜索(博查) → 网页抓取 → LLM 综合成文;全程 SSE 流式展示进度(正在搜什么、找到哪些源) |
| F3.1 | 研究确认弹窗(抄原项目) | 点击地点后先弹确认:① 研究方向预设(综合沿革/战争军事/自然地理/民族风俗/历史人物/古建筑文物/经济商贸/近现代变迁)② 自定义补充指令输入框;确认后才启动。省成本 + 给用户控制感 |
| F3.2 | 断线恢复(抄原项目双通道设计) | 编排器状态持久化(DB):SSE 断开→客户端切独立短轮询端点;页面刷新→凭 taskId 恢复进度与结果;10 分钟级长任务的刚需 |
| F4 | 中文研究报告 | 结构化输出:建制沿革/重大事件/文化风俗/文物遗存/近现代变迁 + **每段带编号引用** + 末尾来源列表;引用编号由代码从搜索结果生成并注入(含标题/URL/摘要/日期/引用原文),LLM 只允许引用已存在的编号,后处理校验剔除幻觉引用 |
| F5 | 资料稀缺度提示 | 当检索源 < N 条时,报告顶部明确标注"资料稀缺",并降级输出行政区划沿革 + 地理背景(此信息总有),不编造 |
| F6 | 历史记录 | localStorage 本地保存研究过的地点列表,可回看 |
| F7 | 分享 | 生成公开只读链接(先简单实现,有链接即可;OG 卡片随 P1 微信分享卡片再做) |
| F8 | 随机探索 | "随便看看"按钮:80% 从预置地点池抽(先以种子池起步——全国重点文保精选 ~100 处,M1 期间扩至 500+ 精选中国及世界人文地点,保证资料丰富),20% 全球纯随机(保留"落到荒野也有故事"的惊喜感,原项目即纯随机含海洋) |

### P1(第二迭代)

- 报告配图管线(架构预留):研究完成后的独立流程——搜图 + vision 模型选 3-5 张高质量图(国内用 qwen-vl/GLM-4V;无 key 时优雅降级为无图);抓取阶段同步收集 og:image 以省一次搜索
- 排除来源重研究(抄原项目):对报告不满意时勾选排除某些来源后重新生成
- 研究日志面板:完整展示规划/搜索/筛选的推理轨迹(对应原项目 reasoning-dialog)
- "节省指标"(抄原项目营销点):分析 N 个来源/约 N 万字/节省人工检索约 N 小时
- 时间线可视化(报告中的事件自动提取成横向时间轴)
- 账号体系 + 跨设备同步(微信登录)
- 未登录限流(anonymousId + 日限 3 次)——P0 不做限流,内测期靠缓存回放与自适应轮次控成本,公测(M2)前上线
- 收藏夹/文件夹
- 阅读优化:目录导航、字体、深色模式
- 移动端手势优化 + 分享到微信卡片
- 重新研究/追加研究("再深挖某一段")
- PDF 导出(内嵌 Noto Sans SC 字体)

### P2(远期)

- 社区贡献史料(用户上传县志片段、老照片,审核后附在报告后)
- 与地方志办/档案馆的内容合作(独家数字化内容)
- 历史地图叠加(民国地图、古今对照)
- 多地点对比研究
- 小程序/App

## 4. 非功能需求

| 类别 | 要求 |
|---|---|

| 成本 | 单次研究成本 ≤ ¥0.25(博查 4-6 轮自适应 × ¥0.036/次 + DeepSeek 约 50K tokens ≈ ¥0.04;实际开支以 M0 实测确认);限流 P0 不做,移至 P1 |
| 可用性 | 搜索层故障自动降级(博查→备选源);LLM 故障切换备用模型 |
| 合规-备案 | **已决策:个人主体,M2 公测前不备案、不公开运营**。M0/M1 阶段本地运行或海外环境(自有域名)内测;正式公测前再完成个人 ICP 备案 + 域名实名 |
| 合规-AI 标识 | 依《人工智能生成合成内容标识办法》(2025.9 施行):页面显著位置标注"AI 生成",报告含隐式标识元数据 |
| 合规-地图 | 中国境内公开服务需审图号底图。路线:天地图(官方背景,风险最低);高德路线作为商业升级备选 |
| 合规-内容 | 历史议题敏感词过滤层 + 报告免责声明(内容来自公开网络,仅供参考) |
| 可观测 | 每次研究记录:轮次、命中源数、耗时、成本、用户满意度(👍/👎) |

## 5. 技术架构(建议)

### 5.1 总体

```
┌─ 前端 Next.js 15 + React 19 + MapLibre GL(天地图瓦片)
│     └ SSE 流式:研究进度/搜索过程/引用发现
├─ 研究编排器(核心自建,适配器模式)
│     ├─ 搜索层接口 SearchProvider ─→ 博查(主) / 备选(fallback)
│     ├─ 抓取层 Fetcher ─→ 自建 readability 抓取(去广告去噪)
│     └─ LLM 层 LlmProvider ─→ DeepSeek(主) / Qwen(备)
│     流程: 地名+坐标 → 研究规划(拆 5-8 个子问题) → 并行搜索
│           → 源筛选去重 → 抓取正文 → 分段综合 → 引用对齐 → 成文
├─ 逆地理编码 ─→ 天地图 API(CGCS2000≈WGS84,无需纠偏;村级粒度备选:民政部县界空间查找,村名由研究阶段反推)
└─ 存储 ─→ MVP:SQLite(研究记录/来源缓存) → 后:PG
```

### 5.2 关键决策与理由

1. **不 fork 原项目改皮,重写核心、参考其交互**。原项目价值在产品构思和 UI 交互(globe + 流式研究面板),其研究编排深度耦合 Valyu 协议。重写编排器 + 借鉴 UI 结构,代码量可控(预估核心 6-8K 行 vs 魔改原项目同样要动 3-4K 行且背着英文债)。
2. **搜索层多源策略(博查 + 智谱,官方定价核实)**:博查 ¥0.036/次(AI 优化结果、长摘要);智谱 search_std ¥0.01/次 / search_pro ¥0.03/次 / search_pro_sogou ¥0.05/次(**覆盖知乎/腾讯生态,文史内容强源**)。阿里千问联网检索 Agent ¥0.022/次但为 Agent 形态集成成本高,OpenSearch 联网搜索 QPS 限 3 不适合。**M0 做 A/B**:同 10 地点博查 vs 智谱各跑一遍,以引用源质量定主力;成本最优组合为「首轮广搜 std ¥0.01 → 缺口补搜 pro → 深挖轮 sogou 打知乎源」,单次搜索费可压至 ¥0.06-0.10。海外源(Tavily/Serper)仅作降级链末端。
3. **LLM 选 DeepSeek**:中文写作质量/价格比最优,国内直连。Qwen 做故障备份。
4. **地图选天地图 + MapLibre**:免费、官方、CGCS2000 坐标系与 WGS84 兼容(研究源里的经纬度直接用,无 GCJ-02 偏移问题)、卫星影像覆盖全国。缺陷:海外影像质量一般、样式美观度不如 Mapbox → 接受,核心场景是中国境内。
5. **坐标系:全链路 WGS84/CGCS2000**,不引入 GCJ-02。若未来切高德需加转换层
6. **Deep Research 即服务格局(2026 调研)**:国内对标物为阿里百炼 qwen-deep-research(规划→多轮搜索→成文一体,单次约 ¥5-15,是自建的 25-75 倍,仅作 M0 质量基线/未来付费"深度模式"选项);海外专用 research API 正集体退役(OpenAI 2026.7 退役、Perplexity 2026.9 停支持),反证自建编排的抗周期性

## 6. 风险与应对

| 风险 | 等级 | 应对 |
|---|---|---|
| **无名地点资料趋零**(最脆弱假设) | 高 | F5 资料稀缺度提示;降级输出"行政区划沿革+地理背景";精选地点池保证随机探索质量;把"查无此地"本身做成诚实的体验 |
| 历史内容敏感/合规 | 高 | 敏感词过滤前置;AI 生成标识;免责声明;内容主体为古代史与地理沿革(风险低),近现代敏感期 prompt 规避 |
| 地图审图合规 | 中高 | MVP 阶段天地图;若正式运营,走审图号申请或接入有资质图商的技术服务许可(预算 5 万/年级别,商业决策) |
| 博查涨价/停服 | 中 | SearchProvider 接口抽象,备选源可切换;结果缓存减少重复研究 |
| 单次成本失控(用户狂点) | 中 | 结果缓存(同地点 30 天内直接回放,键 = 地名 + 坐标)+ 自适应轮次;未登录限流(anonymousId 日限 3 次)移至 P1,公测(M2)前上线 |
| 研究耗时长导致流失 | 中 | 流式展示搜索过程本身就是留存设计(参照原项目);3 分钟内为硬指标 |

## 7. 里程碑

| 阶段 | 内容 | 周期 |
|---|---|---|
| M0 原型验证 | 编排器跑通:10 个代表地点(知名→无名)产出报告,人工评分 | 1 周 |
| M1 MVP | P0 全部功能,内测(朋友/文史社群) | 3 周 |
| M2 公测 | P1 + 备案 + 合规标识上线,开 1-2 个社群渠道 | +4 周 |
| M3 商业化探索 | 付费额度/会员、内容合作,视数据决定 | 视情况 |

**M0 通过标准**:10 个测试地点中 ≥ 7 个报告"值得读完"(3 名以上内测者盲评),单次成本 ≤ ¥0.25(实际开支以实测确认),耗时 ≤ 3 分钟。

## 8. 成本模型(公测期,假设 100 DAU × 3 次/日)

- 研究成本:300 次/日 × ¥0.22 = ¥66/日 ≈ ¥1980/月
- 缓存命中率 40% 后:~¥1200/月
- 基础设施:~¥100/月
- **月成本 ≈ ¥1300-2100**,免费层可承载,付费转化点在"更多次数 + 深度研究模式";若博查成本占比过高,备选方案:首轮 count=10 覆盖广、后续轮次仅在信息缺口时追加(自适应轮次)

## 9. 已决策事项(2026-10-22 定稿)

1. **运营主体与合规路线 → 个人**。天地图免费额度 + 个人身份起步;商业图商授权推迟到有收入后再评估
2. **域名与备案 → 推迟**。M0/M1 不备案:本地运行 + 海外环境内测(自有域名,不面向公众推广);M2 公测前完成个人备案
3. **开源策略 → 确认**:代码开源(MIT),研究 prompt 与精选地点池闭源
4. **付费假设 → 不纠结**,M2 用付费墙实验验证,当前不影响任何设计
5. **P0 从简(2026-10-22 补充)**:限流不做(anonymousId 日限移至 P1,公测前上线);分享仅公开只读链接(OG 卡片随 P1);地点池以种子池(~100 处)起步再扩 500+;结果缓存键 = 地名 + 坐标
